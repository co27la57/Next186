## 二、根因：VGA 读窗没有跟着 CPU 地址一起 ×2

### CPU 侧（移植版是作者的 2 倍 —— 这是**有意**的，不是 bug）

```
移植版 ddr_186.v:996   sdraddr = {memmap_mux[8:0], cache_hi_addr[9:0], 5'b00000}
作者   ddr_186.v:836   sdraddr = {memmap_mux[8:0], cache_hi_addr[9:0], 4'b0000 }
```

低位多补 1 个 0 ⇒ **移植版 CPU 物理 sdraddr = 作者 × 2**。

- 作者：CPU B800:0 → sdraddr `0x2E000`
- 移植版：CPU B800:0 → sdraddr `0x5C000` → DDR `0x080B8000`（**与实测吻合**）

> 为什么 5'b0 是必需的：BIOS 的 MAP 值最大只到 `0x15`。用作者的 4'b0 时
> page 最大 0x15 ⇒ sdraddr 上限 0x57FF0，**够不到** BIOS 所在的 0x7F000；
> 用 5'b0 时 page 0xF ⇒ 0x78000–0x7FFE0，**正好覆盖 0x7F000**（与实测 DDR 0x080FE000 一致）。

### VGA 侧（**没有**跟着 ×2 —— 这就是 bug）

```
ddr_186.v:995   sdraddr = {6'b000001, vga_ddr_row_col + vga_lnbytecount}
```

`6'b000001 << 17 = 0x20000`，row_col 是 17 bit ⇒ VGA 可读窗只有

```
sdraddr 0x20000 – 0x3FFFF   =   DDR 0x08040000 – 0x0807FFFF
```

而 CPU 文本页在 sdraddr `0x5C000` —— **在窗外，VGA 根本够不到**。

### 那为什么 stage-1 能显示？

现 `VGA_TEXT_ROWCOL = 17'h14000` ⇒ sdraddr `0x34000` ⇒ DDR `0x08068000`。
这正好是**复位态 MAP 下 seg 0xB → page 6** 的位置（page6: `6*0x8000 + 0x4000 = 0x34000`），
也就是 **bootstrap 写字的地方** ⇒ "Searching BIOS" 能显示。

BIOS 起来后做 MAP init（写端口 0x80–0x8F）把 seg 0xB 改成 page 0xB（恒等），
文本搬到 sdraddr `0x5C000` / DDR `0x080B8000` ⇒ **飞出 VGA 窗口** ⇒
VGA 继续显示 `0x08068000` 上的旧内容 ⇒ **屏冻在 stage-1 那串**。
（与 111/112th 现象、ILA `scraddr=0 / text=3` 完全自洽。）

# ★★ 125th 修正（2026-09-28）：上面第三节的"×2 改法"是错的，已回退

## 现象
按第三节改完后**屏又花（读垃圾）**。ILA 抓到 `dbg_vga_scraddr = 0x6000`（非 0！）、
`dbg_cpu_iaddr = 0xFFDAC`、`lport = 0x03DA`、`dbg_cpu_halt = 0`。

## CPU 没崩
用户断电重上电，`0x080B8000` 又打出同一整屏 DOS ⇒ 硬件/代码路径完好。
`lport=0x3DA` = VGA Input Status Reg.1（bit3=vblank）；asm L3413 `mov dx,3dah` →
L3422 `in al,dx ; get vblank` = **int16 的 wf_loop(L3415-3426)** —— DOS 在 `C:\>` 调
INT 16h 等键时 BIOS 拿 vblank 当超时计时器。**"卡在 0xFFDAC"= "正在等键盘"，不是卡死。**

## 花屏真因：4bit 加法器溢出
L1060 的 `{{1'b0,scraddr[15:13]} + ROWCOL[16:13], scraddr[12:0]}` 高位加法只有 **4bit**。
- 第三节把 ROWCOL 改成 0x1C000 ⇒ `[16:13] = 14`
- scraddr = 0x6000 ⇒ `[15:13] = 3`
- **14 + 3 = 17 → 4bit 回绕成 1** ⇒ `row_col = 0x2000` ⇒ `sdraddr = 0x42000` → DDR 0x08084000（垃圾页）

根本错误：×2 了 ROWCOL 与前缀，却**没 ×2 scraddr 项**；且 17bit row_col 装不下 2×(ROWCOL+scraddr)。

## 正确修法（已应用）：内部保持"作者单位"，只在输出口 ×2
依据：移植版 CPU 地址路径 `{page,line,5'b0}` vs 作者 `{page,line,4'b0}` ——
page/line 译码完全相同，只差低位补零一位 ⇒ **同一 CPU 地址的物理 sdraddr 恒为作者的 2 倍**。
所以只要在 VGA 输出处把"作者地址"×2 即可，scraddr 相加、每行 +40、回绕等内部逻辑全部原样保留。

| 位置 | 值 |
|---|---|
| `VGA_TEXT_ROWCOL` | **`17'h0E000`**（回退到作者原值） |
| `VGA_GRAPH_ROWCOL` | **`17'h08000`**（回退到作者原值） |
| L997 输出 | **`{5'b00001, vga_ddr_row_col + vga_lnbytecount, 1'b0}`** |

`{5'b00001, X[16:0], 1'b0}` = `0x40000 + 2X`（5'b00001 占 [22:18]；X 占 [17:1]；bit0=0）。

零溢出验证：
- `row_col` 最大 = 0xE000 + 0xFFFF = **0x1DFFF < 0x20000**（17bit 装得下）
- 加法器最大 = 7 + 7 = **14 ≤ 15**（4bit 装得下）

验算：
- scraddr=0 → `0x40000 + 2×0xE000 = 0x5C000` → DDR **0x080B8000** = CPU B800:0 ✓
- scraddr=0x6000 → `row_col = 0xE000+0x6000 = 0x14000` → `0x40000 + 0x28000 = 0x68000` → DDR **0x080D0000**

## 待上板判别
dump `0x080D0000`（本修法预测页）vs `0x080C4000`（"线性/2"模型页），哪个有文本就坐实哪种地址模型。

## 教训
改"基址 + 偏移"类公式时，**偏移项也必须同步缩放**；动手前先看清加法器位宽。

# 126th：开机花屏的成因 + "每八个字符重复"的成因（实测现象解释）

## 现象（121st 版本上板）
开机瞬间花屏（读垃圾）；随后**能辨认出已进入 DOS**。残留一个"每 8 个字符重复"的横向重复感。

## 一、开机花屏：文本页在启动途中"搬了一次家"（非基址算错）

启动两段，CPU 写字的**物理页被 BIOS 的 MAP init 中途改掉**：

| 阶段 | MAP 状态 | seg 0xB → page | 文本 sdraddr | DDR |
|---|---|---|---|---|
| stage-1 bootstrap | **复位态** | page 6 | `0x34000` | `0x08068000` |
| BIOS 做完 MAP init 后 | BIOS 写端口 0x80–0x8F | page 0xB（恒等） | `0x5C000` | `0x080B8000` |

- 121st / (B) 都把 VGA 固定指向 `0x5C000`（= MAP init **之后**那页）。
- bootstrap 期间该页还没人写（上电后未初始化 DDR）⇒ **读垃圾 ⇒ 开机花屏**。
- BIOS 跑完 MAP init、DOS 开始写 B800:0 后，该页才被填真实文本 ⇒ **可读 DOS** ✓

⇒ **"花屏只在开机时才有"不是基址错，而是"基址只能固定一个、物理页中途换了一次"。**
原版代码（`0x14000`→`0x34000`）指向 bootstrap 那页 ⇒ 永远显示 "Searching BIOS"、永远看不到 DOS；
121st/(B) 指向 DOS 那页 ⇒ **牺牲开机那一两秒**。这是取舍，属 cosmetic，**无法用静态基址同时满足两段**
（若要两全，需让 VGA 跟着 MAP 走，例如监测端口 0x8B 的写入再切基址，代价大、暂不必要）。

## 二、"每八个字符重复"：121st 差两步

1. **每行步进没跟着 ×2（主因）**
   - 作者 1 个 sdraddr 单位 = **4 字节**（作者 sdraddr = 线性/4）⇒ 80 字符 = 160 字节 = **40 单位** ⇒ 作者 `+40` 正确
   - 移植版 1 单位 = **2 字节** ⇒ 160 字节 = **80 单位** ⇒ 应为 **+80**
   - 121st 仍是 `+40` ⇒ **每行只走一半** ⇒ 横向重复/错位。
2. **4bit 加法器溢出**：`ROWCOL[16:13]=14 + scraddr[15:13]` 在 scraddr ≥ 0x4000 时回绕（ILA 实测 scraddr=0x6000）。

## 三、为什么 (B) 正好补上这两处（结论：不要回退到 121st）

(B) = ROWCOL 退回作者值 + **输出口 ×2** `{5'b00001, row_col+lnbytecount, 1'b0}`：

- scraddr=0 时 → `0x40000 + 2×0xE000 = 0x5C000`，**与 121st 数值完全相同**
  ⇒ 显示 DOS 的效果一模一样（121st"有戏"的那部分 (B) 全都有）
- `+40` 在输出处被 ×2 自动变成 **80** ✓ 修掉重复
- scraddr 相加仍在作者单位内进行（最大 `0x1DFFF`，加法器 `7+7=14≤15`）✓ 不溢出

⇒ **(B) ⊇ 121st**。回退到 121st 只会保留"每 8 字符重复"，没有任何收益。

## 量化
- **步进 = 80 字符/行 ✓**（(B) 的 `+40`×2 生效，重复消失）
- **基址偏移 = 16 字符 = 16 移植单位 = 8 作者单位 = 恰好一个 burst(8字)**
- 目标：显示行应为 `帧缓冲[80k, 80+80k)`

## 修复（已应用）
`ddr_186.v:1008`
```verilog
{5'b00001, vga_ddr_row_col + vga_lnbytecount - 5'd8, 1'b0}
```
→ `sdraddr = 0x40000 + 2×(row_col + lnbytecount - 8)`；scraddr=0 时 = `0x5C000 - 0x10 = 0x5BFF0`
→ 显示从帧缓冲 char 0 开始 ✓

**为什么 -8 不能加进 `VGA_TEXT_ROWCOL`**：L1065 endframe 公式
`{{1'b0,scraddr[15:13]} + ROWCOL[16:13], scraddr[12:0]}` **只取 ROWCOL[16:13]、丢掉低 13 位**，
所以 ROWCOL 必须 0x2000 对齐；-8 只能加在输出口求和里。

**宽度安全**：`A(17b) + B(8b) - 5'd8` 自定宽 = 17bit；`A ≥ 0xE000` 无下溢；
concat 仍 5+17+1 = 23bit → 零扩展进 24bit sdraddr ✓。只改 sdraddr 计算，不动 `vga_lnbytecount`
本身 ⇒ 扫描行结束判据（`:1080`）不受影响 ✓。

| 其他 | 按 `offset = 2×scraddr − 16` 反推 | 按实测重算 |

另一疑点：BDA 40:50/51 = (col 4, row **24**)，而 `C:\>` 在 row18，两者不符 ⇒ 需要一次

## 132nd：水平偏移已消除 ✓；`scraddr = 0000` ⇒ 880 在我方链上，已减 11 行

1. 把 concat 末位改 `1'b1` 后，**水平偏移消失** ✓
2. ILA 实测 **`dbg_vga_scraddr = 0000`** ⇒ 走判定树的"我方地址链"分支，

**已应用（`ddr_186.v:1008`）**：
```verilog
{5'b00001, vga_ddr_row_col + vga_lnbytecount - 9'd448, 1'b1}
```
（= 原 `-8` 再加 **11 行 × 40 = 440** 作者单位，合并成 `-448`）

### 为什么这个改动是安全的
- **880 = 11×80 是整数行** ⇒ 纯垂直平移，**已修好的水平对齐完全不受影响**
- **-895 是加在基址上的常数**，`scraddr` 仍照常参与计算 ⇒ **滚屏功能保留**
- 宽度：`9'd448` 为 9bit，`A(17b)+B(8b)-9'd448` → 17bit；`A ≥ 0xE000` ⇒ `0xDE40 > 0` 无下溢

# 135th：★ 底部 7 行乱码的真因 = `v240[0]` 被硬编码（强制 480 行）—— 不是基址常量

## 先排除 (b)
当前 dump 证明帧缓冲内容**完好**：row0=`WARRANTY…`、row18=`C:\>`、row19-24 为空 ✓
⇒ 排除"BIOS 滚屏写坏内存"。

## 但 (a)「减 560 字符常量」也不成立
照片里 `Copyright 2001-2005`(r10) 与 `Driver Version`(r11) 之间**多出一个空行**，
而 dump 里 r10、r11 **紧邻无空行**。
**纯常量基址偏移只会整体平移，不可能在屏中间插出空行** —— 所以 134th 提的
「`- 9'd448` → `- 9'd168`」会把顶部也一起旋转掉，是错的，**没有采用**。

## 真因：行数被强制成 480

`ddr_186.v:201`
```verilog
wire vga_end_frame = vga_ddr_row_count == (v240[0] ? 479 : 399);
```

| | `v240[0]` 赋值 |
|---|---|
| 作者 `Next186_SoC-master/ddr_186.v:869` | `v240[0] <= vde >= 10'd400;`（由 CRTC 垂直显示结束寄存器决定） |
| 移植版（原 `L1093`） | `v240[0] <= 1'b1;` ← **硬编码** |

**后果链**（`L203` `vga_repln = vgatext ? (half?7:15) : ...` ⇒ 每字符行 16 扫描行）：

- 400 行 ÷ 16 = **25 字符行** = 正好 4000 字节文本页 ✓
- 480 行 ÷ 16 = **30 字符行** ⇒ 多出 5 行必然读到文本页之外

⇒ **屏底 ~7 行乱码**，其中几行恰好读成空白，就是那个"莫名多出的空行"。

## 修复（已应用）
```verilog
v240[0] <= vde >= 10'd400;   // 恢复作者原逻辑
```
`vde` 在移植版 `L269` 已有 `wire [9:0] vde;`，可直接用。

**这是本轮最值的一处**：不是再调一个魔数，而是**把被改坏的一行逻辑恢复成作者写法**，
并且一次性解释了"底部乱码"和"多出的空行"两个现象。

## 预期
屏底乱码消失，25 字符行正好铺满一屏，`C:\>` 后接闪烁光标，下方为空白行。

## 138th（最终方案）：锁 640x480 60Hz + 行推进钳位

> （400 行虽是 VGA 文字模式 3 的标准，但本机不同步，必须锁 640x480。）

**① L1099：恢复硬编码，锁死 640x480**

（代码里已注明「不要再改这一行」）

# 139th：★ 更优解 —— 那 5 行"本来就没有数据"，用"截断可见区"代替钳位

| | 做法 | 评价 |

```verilog
wire sdon = s_displ_on[17+vgatext[1]] & (vcount <= vde) & (~vgatext[1] | (vcount < 10'd400));
```
