Next186 无探针定位：devmem 三区 + RS232 判别法（2026-09-27 修订 v2）
================================================================
【关键纠正】devmem 单次只能读一个 32-bit 字：
   正确：  devmem 0xXXXXXXXX 32
   错误：  devmem 0xXXXXXXXX 512   （devmem 没有 count 参数，会直接报参数错误）
批量读 N 个字，且地址是 16 进制时，必须用 bash 的 C 风格 for 循环
（GNU seq 对 0x 十六进制支持随版本而异，BusyBox seq 多不支持，别用）：

   for ((a=0x起始; a<=0x末尾; a+=4)); do printf "%08x: " $a; devmem $a 32; done

末尾 = 起始 + 字节数 - 4（即最后一个字的地址）。每读一个字步进 4 字节。
若板子 shell 是 sh/dash/BusyBox（非 bash），把 0x 地址换成十进制即可：
   0x08000400=134218752  0x080005FC=134219260
   0x080FFC00=135265280  0x080FFC3C=135265340
   0x080FE000=135258112  0x080FE0FC=135258364
   0x080F0100=135201024  0x080F010C=135201036
   0x08068000=134643712  0x08068F00=134647552

================================================================

【前提】屏幕只有 "Searching BIOS"（stage-1 文本，B800:0 → DDR 0x08068000）。
  Log1.txt 已确认：stage-1 文本完整、BDA[0]=0x3F8（UART 探测到）、
  BIOS "Next" 头在 0x080FE000 完整，但无 stage-2 横幅、无 "No boot device"。
  ⇒ stage-2 已启动，崩在 UART 探测之后、横幅打印之前。下面坐实崩点。

----------------------------------------------------------------
0) VGA 文本页（stage-2 是否写过屏 / 是否清屏）
   读 0x08068000..0x08068F00（960 字）：
   for ((a=0x08068000; a<=0x08068F00; a+=4)); do printf "%08x: " $a; devmem $a 32; done
   判读：只有 "Searching BIOS..." 且无 "Next186 Flea Ohm..." 横幅 ⇒ stage-2 没到 prts。

----------------------------------------------------------------
1) BDA 区（进度标记，重点看内存大小字）
   读 0x08000400..0x080005FC（512 字节 = 128 字）：
   for ((a=0x08000400; a<=0x080005FC; a+=4)); do printf "%08x: " $a; devmem $a 32; done
   判读：
   - 偏移 0x00（DDR 0x08000400）= BDA[0]，已知 = 0x000003F8（COM1 基址，UART 成功）。
   - 偏移 0x13 处 2 字节（字在 DDR 0x08000410）= 内存大小字，BIOS 早期写 640(=0x0280)。
     小端 ⇒ 0x08000413 字节=0x80、0x08000414 字节=0x02。
     若在这 ⇒ stage-2 跑到 BDA 初始化；若不是 ⇒ 崩在 BDA 初始化之前。
   - 其余 BDA 字段（设备清单、COM 参数等）也能看出初始化推进到哪。

----------------------------------------------------------------
2) 栈回写内容（看调用链 / 返回地址，定位崩在哪一个函数）
   读 0x080FFC00..0x080FFC3C（64 字节 = 16 字）：
   for ((a=0x080FFC00; a<=0x080FFC3C; a+=4)); do printf "%08x: " $a; devmem $a 32; done
   判读：SS:SP=F000:FC00 = DDR 0x080FFC00。栈顶附近应是从 stage-2 各初始化函数压入的
   返回地址（均在 0x080FE000..0x080FFFF 区间）。对照 sim/dis_full.out 反汇编，
   若某返回地址落在某函数体内 ⇒ 定位崩在哪个调用。
   若栈里出现非代码区间的值 / 全 0 / 全相同 ⇒ 栈被踩或复位态未推进。

----------------------------------------------------------------
3) BIOS 代码区完整性（指令是否被垃圾回写砸坏）
   读 0x080FE000..0x080FE0FC（256 字节 = 64 字）：
   for ((a=0x080FE000; a<=0x080FE0FC; a+=4)); do printf "%08x: " $a; devmem $a 32; done
   判读：前 4 字节应为 "Next"（4E 65 78 74）。重点对照 dis_full.out 该区间的指令字节，
   若有字节与 images/BIOS_Next186.bin 不一致 ⇒ 指令被缓存回写覆盖 ⇒ 取指跑飞源。

----------------------------------------------------------------
【RS232 循环判别】int18h 的 sloop 把收数字节顺序写入 F000:0100 = DDR 0x080F0100。
   循环：call srecb(0x80FF55B); mov [si],ah; inc si; dec bx; jne
   (a) PC 侧串口工具 115200bps 发 0x55（'U'），可连发几个。
   (b) 读 RS232 缓冲首部：
   for ((a=0x080F0100; a<=0x080F010C; a+=4)); do printf "%08x: " $a; devmem $a 32; done
   判读：
   - 0x080F0100 首字节 = 0x55（且随发数增多依次落到 +1/+2…）⇒ 真在 RS232 收数循环。
     但此情形与"屏只显示 Searching BIOS"矛盾，说明 VGA 打印另有问题。
   - 发了多个字节后 0x080F0100 仍全 0 ⇒ CPU 不在 RS232 收数循环（与当前 Log1 一致）。

----------------------------------------------------------------
【结论分支】
 - 0)无横幅 + 1)无 0x0280 + RS232 空  ⇒ 崩在 stage-2 极早期（BDA 初始化之前）。
 - 0)无横幅 + 1)有 0x0280 + 2)栈链指向某函数 + RS232 空 ⇒ 崩在 BDA 初始化之后、
   某初始化函数内（结合 dis_full.out 定位）。
 - 3)代码区有字节 ≠ bin ⇒ 缓存回写砸了 BIOS 指令，是取指跑飞根因。
 - RS232 有字节 ⇒ 真在 RS232 循环（问题转向 VGA 为何没上屏）。
