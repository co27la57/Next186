# 修复后波形判读（2026-10-31 14:29，AXI 总线级 53 探针）

数据存 `ila_postfix_20261031.csv`，1024 拍 @50 MHz = 20.5 µs。

## 一、读侧：2 拍/beat 已生效 ✓

7 个读突发，每个 44~45 拍 / 16 beat = **2.81 拍/beat**（修复前 4.19）。

逐拍（AR@206）：

```
208-220: rv=0 rd=1        ← 13 拍等首 beat（PS 侧排队延迟）
221:     rv=1 rd=1  beat1
222:     rv=1 rd=1  beat2   ← 连拍
223:     rv=1 rd=0        ← rready 拉低（PUSH_1）
224:     rv=1 rd=1  beat3
226:     rv=1 rd=1  beat4   ← 之后恒为「接1拍、停1拍」
```

**beat 本身已从 4 拍压到 2 拍**，与改法预期一致。剩下的 13 拍是 AR→首 beat 的排队延迟，
那是 PS/HP0 侧决定的，master 端改不动（要隐藏它需要 outstanding AR / 预取，属另一个量级）。

## 二、写侧：每个 64 字节要 80 拍 —— 现在最大的单笔浪费

3 个写突发，全部 **80 拍 / 16 beat = 5.00 拍/beat**。逐拍：

```
512: AW 接受
516: wvalid=1 wready=1   beat1
517-520: 空 4 拍
521: wvalid=1 wready=1   beat2
522-525: 空 4 拍
526: beat3 ...
```

`wready` **恒为 1**、`wvalid` 每 5 拍才脉冲一次 ⇒ **限速的是我们自己，不是 DDR**。

原因在 `top_zynq7010.v` 的写 FSM：每个 beat 都完整走一遍
`W_ISSUE → W_PRE → W_L → W_H → W_WAIT_W` 五个状态，其中只有 W_L/W_H 两拍在搬数据。

## 三、改之前必须先尊重的两条硬约束

1. **`cache_read_data` 必须恰好 2 个脉冲/字。**
   `cache_controller.v` 的 `wb_pcnt` 按脉冲计数，字序号是 `wb_pcnt[5:1]`；
   注释明确写着这条是"结构性保证，与 AXI wready 停顿无关，不依赖任何节拍假设"。
   ⇒ 写 FSM 每 beat 仍要给 **2 个 `cache_read_data` 脉冲**（即保留 W_L、W_H 两拍），不能图省事压到 1 拍。

2. **`W_PRE` 不是空的（第二十二次修复）。**
   它存在的理由是"多等一拍，让 `ddr_186` 的 `cache_line_start` 在 W_L 拍前到达，
   把 `lowaddr` 归零，消除写回首字 +1 word 偏移"。
   ⇒ 只能**在突发开头等一次**，不能每 beat 都等。

## 四、因此下一步方案（未实施）

把 per-beat 的 5 状态环改成：**突发开头 `W_ISSUE → W_PRE` 一次，之后 `W_L ↔ W_H` 循环**
（并在 W_H 里处理 wready 停顿）：

| | 现在 | 改后 |
|---|---|---|
| 每 beat 状态 | W_ISSUE, W_PRE, W_L, W_H, W_WAIT_W（5 拍） | W_L, W_H（2 拍，wready=1 时） |
| 每写突发 | 80 拍 | **~36~40 拍** |
| `cache_read_data` 脉冲数 | 32（2/字）✓ | 32（不变）✓ |
| `W_PRE` 次数 | 每 beat 一次 | **每突发一次**（保住 #22） |

收益：本抓包里写占 3×80=240 拍（23%），改后约 120 拍 ⇒ 省 12% 总线；
写多的工作负载（上一次抓包是 18 个写突发）收益会大得多。
