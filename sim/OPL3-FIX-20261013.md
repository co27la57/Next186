# OPL3 修复与板上观测（2026-10-13）

板上 VGM 播放时四盏通道灯全灭，断点在 OPL3 命令 FIFO 之前。

`opl3.v` 把 `opl3_in` 当作 fall-through FIFO 使用：Z80 在 I/O 读周期直接采样 `qdata`，同时产生 `rdreq`。原 XPM 实例没有设置 `READ_MODE`，Vivado XPM 默认是 `READ_MODE="std"`、`FIFO_READ_LATENCY=1`，所以 `qdata` 不会在该读周期前准备好。生产 `opl3_in` 的 `.rst(rst)` 还引用了未声明的隐式线网，Vivado 曾报告 `Net rst ... does not have driver`。

本次修复：

- 给 `opl3_in` 增加显式 `rst` 端口，并由 `opl3.reset` 驱动；
- 把 OPL3 FIFO 明确设置为 `.READ_MODE("fwft")`；
- 给 `sndfifo` 增加显式复位，并从 `ddr_186` 的系统复位传入，修复同类 I2S 音频 FIFO 复位悬空；
- LED0～LED3 继续对应 OPL3 通道 0～3，显示最近约 50 ms 内的实际通道样本活动；
- 为下一次上板增加 OPL3 ILA 状态：CPU/Z80 地址低字节、FIFO 队首数据、`qempty`、sequencer `ready`、外部 I/O 读写事件和通道 sample-hit。

验证结果：

- OPL3 OOC Vivado 综合：`132 Infos, 107 Warnings, 0 Critical Warnings, 0 Errors`，并确认 XPM 参数 `READ_MODE=fwft`；
- 顶层 Verilator lint：退出码 0；
- FWFT 仿真启动阶段已出现非零 OPL3 样本（修复前整核测试为四路全零）；
- LED 定向回归：0 errors，覆盖通道隔离、±16 门限、50 ms 保持和复位。

整核仿真的人工音符断言仍有 9 项失败；它不能替代真实 VGM 播放验证，下一次位流上板时应先观察 ILA 的 `probe19` 和 `probe10`，再看四盏灯。

静态 ILA 总宽度保持 **200 bit**。原 VGA `dbg_vga_ramaddr_at_ack`、重复的 `dbg_vga_ack_pulse`、以及不能证明当前同源时钟 CDC 的 `dbg_vga_cdc_at_wr` 已在外围工程的 `Network.xdc` 中注释/换用；对应 RTL 旧寄存器保留但不再占用 ILA 槽位。
