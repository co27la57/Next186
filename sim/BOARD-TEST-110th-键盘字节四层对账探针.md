# 键盘字节链路四层对账 —— 探针与触发条件

日期: 2026-10-10
起因: 干净重启后(已排除 BDA 状态污染)实测映射仍然错:

| 注入 | DOS 显示 | BIOS 表应该显示 |
|------|----------|-----------------|
| `0x23` | `h` ✓   | `h` |
| `0x24` | `4` ✗   | `j` (row20)；`4` 是 row51 = 扫描码 `0x05` |
| `0x05` | `@`     | `4` |

而 `kbd_gpio_inject -V` 已证明 **PS 侧写 sysfs 再读回 9 根线逐位全对**，
所以字节是在 EMIO 之后被改写的。四层探针用来定位**在哪一级**被改。

---

## 一、探针清单（13 个，全部 `keep = "true"`）

### 探针组 A —— `kbd_gpio_rx.v`（EMIO 原始引脚，第 0 级）

| 信号 | 位宽 | 含义 |
|------|------|------|
| `dbg_emio_data` | 8 | PS 经 EMIO 送到 PL 的**原始引脚**（选通为高时采样） |
| `dbg_emio_stb`  | 1 | 选通引脚电平 |
| `dbg_rx_data`   | 8 | 出队时锁存的字节（即将交给 8042 的那个） |
| `dbg_popped`    | 1 | 本拍是否真的交出去了 |

### 探针组 B —— `KB_8042.v`（8042 输出缓冲，第 1–3 级）

| 信号 | 位宽 | 含义 |
|------|------|------|
| `dbg_vk_data`  | 8 | 进入 8042 的字节 |
| `dbg_s_data`   | 8 | **实际被装进**输出缓冲 `s_data` 的字节 |
| `dbg_dout`     | 8 | 80186 真的从端口 `0x60` 读到的字节（经 `dout` mux 之后） |
| `dbg_sel_dout` | 2 | `dout` 走哪一路：`0`=s_data / `1`=cmd 状态口 / `2`=ctl_outb 命令字节 |
| `dbg_vk_valid` | 1 | `vk_valid`（电平） |
| `dbg_vk_ready` | 1 | `vk_ready`（= `~OBF & ~MOBF`） |
| `dbg_OBF`      | 1 | 8042 输出缓冲满标志 |
| `dbg_ctl_outb` | 1 | 80186 发了 `0x20` 读配置命令但还没读 `0x60` |
| `dbg_src`      | 2 | 字节从哪条通路进来：`0`=注入 / `1`=自检应答 / `2`=物理键盘 / `3`=鼠标 |

## 二、判读表（**核心**）

抓一次波形，从上往下看**第一个出现 0x24 之外的值**在哪一层：

| 现象 | 结论 |
|------|------|
| `dbg_emio_data` 已经是 `05` | 字节在 **EMIO 引脚**上就变了 → 查 PS 侧 GPIO 或 EMIO 复用冲突（GEM0/SDIO-CD 也走 EMIO） |
| `dbg_emio_data=24` 但 `dbg_rx_data=05` | 在 **`kbd_gpio_rx` 的同步/FIFO** 里被改 → 查采样时序 |
| `dbg_rx_data=24` 但 `dbg_s_data≠24` | **另一条通路塞进了字节** → 看 `dbg_src`，若是 `1`/`3` 就是自检应答或鼠标在掺和 |
| `dbg_s_data=24` 但 `dbg_dout≠24` | **`dout` 三选一 mux** 把数据口读走了 → 看 `dbg_sel_dout` 是否为 `1`/`2` |
| 四层全是 `24` | 链路完全正常，问题在 **CPU/BIOS 之后**（但表已证明 67/67 正确，此路应排除） |
| `dbg_popped` 长时间为 0 | FIFO 堵死（`vk_ready` 恒 0）→ 看 `dbg_OBF` / `dbg_ctl_outb` |

## 三、触发条件

### 推荐触发（抓一个完整字节的生命周期）

```
Trigger mode : BASIC
条件         : dbg_emio_stb  == 1     (上升沿, ILA 配 "上升沿" 或 "== 1")
位置         : 窗口前 256 拍 / 后 256 拍
Capture depth: 2048
```

**为什么用 `dbg_emio_stb` 上升沿**：一个字节从写入到被 80186 读走约 6 ms，
按 `clk_cpu` 25 MHz 算是 ~15 万拍，远超 2048 深度的窗口。
所以**不要试图一帧装下整个过程** —— 用选通沿触发拿到入口，
再靠 `dbg_popped` / `dbg_vk_ready` 的时序关系判断是否交出。

### 备选触发

| 想看什么 | 触发条件 |
|----------|----------|
| 只看入队是否正常 | `dbg_vk_valid` 上升沿 |
| 抓 FIFO 堵死 | `dbg_vk_valid == 1 && dbg_vk_ready == 0` 持续 > 1000 拍 |
| 抓字节被换掉 | `dbg_s_data != dbg_vk_data` |
| 抓 mux 抢数据口 | `dbg_sel_dout != 0` |

### 操作步骤

```sh
# 1) 先重启板子, 等 guest 到 C:\> 提示符（我会用 SSH 读屏确认）
# 2) 单发一个字符（只发 make，不发 break，便于对齐）
./kbd_gpio_inject -r 24      # 然后按一次回车
# 3) ILA 上按上述条件触发，抓 2048 拍
# 4) 把波形里的四层数值发我
```
