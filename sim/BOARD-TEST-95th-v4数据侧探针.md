## 2. 要读什么

| 信号 | 正确时应为 | 说明 |
|---|---|---|
| **`dbg_rd_reg[3:0]`** | **`2`** | 写回 line 2 时送出的数据的高半字节 |
| **`dbg_rd_reg[8:4]`** | **`2`** | 该写回**属于**的行号 |
| **`dbg_wb_reg[3:0]`** | **`2`** | 填充 line 2 时拿到的数据的高半字节 |
| **`dbg_wb_reg[8:4]`** | **`2`** | 该填充**属于**的行号 |
| `dbg_dbg5[7:0]` | 应仍为 `0xA0` | 确认这版跑上了 |
| `dbg_spur_wb_n` / `dbg_spur_rd_n` | `00` / `00` | 95th 修复仍在生效 |
| `dbg_bufwb_a[14:0]` | 上次 = `0x3c06` | 最后一次缓冲行写回的 hiaddr |

**判据（一句话）**：低半字节 == 行号 ⇒ 自己行的数据；**不相等 ⇒ 拿到了别行的数据**。

## 3. 为什么这样能判

自测图案是 `byte@m = (m>>2)&0xFF` ⇒ 缓冲行 k 的**任何一个字**的字节都是 `(k*16+w)&0xFF`
（w = 0..15）⇒ **高半字节恒为 `k & 0xF`** ⇒ 高半字节直接就是来源行的身份证。

**台架已用注入验证过**（TB 加了 `inject_fill_shift` 人为把填充地址 +N 行）：

```
inject=0 → write-back{idx=02 nib=2}  fill{idx=02 nib=2}    两处都自洽
inject=1 → fill{idx=02 nib=3}
inject=3 → fill{idx=02 nib=5}
inject=4 → fill{idx=02 nib=6}      <-- 正是板上那个 +4 的签名
（写回那一侧始终 nib=2，探针能分开两侧）
```

## 4. 怎么判读

| 观测 | 结论 | 下一步 |
|---|---|---|
| 写回 `nib != idx` | **写回送出了别行的数据**（地址对、数据错）⇒ DDR 里就是错的 | 查写回的 BRAM 端口 A 读地址（`wb_way`/`wb_hiaddr`/`word_a`）|
| 写回 `nib == idx`，填充 `nib != idx` | **填充读错了地址**（DDR 完好）| 查填充命令被接受那一刻的 `sdraddr`（与 v3 结论冲突 ⇒ 说明是选择性/竞态）|
| 两处都 `nib == idx` | 这次没抓到 ⇒ 位移发生在别的行/别的时刻 | 把 `[0x80]`/`[0x180]` 的实际值再报一次，我改成针对 line 6 或改成"任一行" |
