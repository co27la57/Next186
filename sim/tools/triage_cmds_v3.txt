=====================================================================
Next186 上板 triage v3  —— 入口跳转 bug 已修后的“CPU 到底卡在哪”
=====================================================================
背景（2026-09-27 新 dump 已证实）：
  * bootstrap 末跳已改到 F000:E05B。板上 0x080FE05B = 0xFA(CLI)，
    其后 cli;cld;mov ax,30h;mov ss,ax;mov sp,100h;... 完整冷启动序
    => 入口已正确，CPU 不再是“跳到垃圾”。
  * BDA 已被深度初始化：40:00 COM1=3F8 / 40:08 LPT1=378 /
    40:10 设备字=0020 / 40:13 内存=640KB / 40:49 显示模式=03 /
    40:4A 列数=80 / 40:50-51 光标(列4,行24) / 40:1A-1C 键buf=1E
  * 40:6C 定时器 tick = 0x681 = 1665 tick ≈ 91.5 s
    （BIOS int08 在 L496-498 里 add word ptr [6ch],1 —— 已核对源码）
    => BIOS 装了 INT08、开了中断、PIT 在走。**CPU 大概率没死。**
  * 但屏上仍只有 "Searching BIOS on SDCard (last 8KB and first sectors)...."
    => 症状是“屏冻在 stage-1 文本”，与已知的 VGA 文本基址 bug(111/112th) 吻合。

本次要回答 3 个问题：
  A. BIOS 还活着吗？（tick 是否还在涨）
  B. 若活着，它停/等在哪个调用链里？（看栈里的返回地址）
  C. BIOS 到底把字写到了哪一页？（证明只是显示没跟上，还是根本没打印）

---------------------------------------------------------------------
[测试 A] 活性确认（最关键、最便宜）—— 隔 5 秒读两次 tick 计数
---------------------------------------------------------------------
devmem 0x0800046C 32
sleep 5
devmem 0x0800046C 32

判读：
  两次值不同（应差 ~90）  => BIOS 活着、中断在跑 => 问题在显示/或在等某设备
  两次完全相同            => CPU 真卡死（tick 不涨），继续做 B

---------------------------------------------------------------------
[测试 B] 栈内容 —— 定位调用链 / 卡死点
---------------------------------------------------------------------
真 BIOS 栈：SS=0x0030, SP<=0x100  => 线性 0x300..0x400  => DDR 0x08000300..0x080003FF
（注意：不是之前误判的 0x080FFC00；BDA 从 0x400 起，栈紧贴其下）

for ((a=0x08000300; a<=0x080003FC; a+=4)); do printf "%08x: " $a; devmem $a 32; done

判读：栈里的 16 位值若落在 F000:xxxx / C000:xxxx 就是返回地址，
      拿它去 BIOS_Next186.asm 里查偏移即可定位卡在哪个子程。

---------------------------------------------------------------------
[测试 C] 找出 BIOS 真正写字的那页（验证“只是显示没跟上”）
---------------------------------------------------------------------
C1) VGA 端口当前读取页（BIOS 重设 row_col 后改读这里；112th 已实测清零它会黑屏）
for ((a=0x0805C000; a<=0x0805C0F0; a+=4)); do printf "%08x: " $a; devmem $a 32; done

C2) bootstrap 阶段文本页（已知有 "Searching BIOS..."，作对照基准）
for ((a=0x08068000; a<=0x080680F0; a+=4)); do printf "%08x: " $a; devmem $a 32; done

C3) 恒等映射下的 B800:0（线性 0xB8000 => DDR 0x080B8000），找 Neptune 横幅
for ((a=0x080B8000; a<=0x080B80F0; a+=4)); do printf "%08x: " $a; devmem $a 32; done

判读（字符取每个 32 位字的低半/低字节，偶数字节是字符、奇数是属性）：
  在 C1/C3 里找到 "Next186 NeptUNO SoC PC BIOS" 或 "MB SD Card"/"PS2 KB detected"
    => BIOS 其实在正常工作、只是 VGA 没跟着切页 => 纯显示 bug，CPU 没卡
  三页都没有，且 A 显示 tick 还在涨
    => BIOS 在等某个设备（SD / 键盘 / 鼠标），看 B 的返回地址定位
  三页都没有，且 A 显示 tick 冻住
    => 真卡死，按 B 的返回地址反查 asm

---------------------------------------------------------------------
[附带] 仍建议保留的基线（和 v2 一样，便于和上一轮 diff）
---------------------------------------------------------------------
for ((a=0x08000400; a<=0x0800047C; a+=4)); do printf "%08x: " $a; devmem $a 32; done
for ((a=0x080FE058; a<=0x080FE098; a+=4)); do printf "%08x: " $a; devmem $a 32; done

---------------------------------------------------------------------
注意
---------------------------------------------------------------------
* devmem 只能单字读：devmem <addr> 32 （不要带 count）
* 批量用 bash C 风格 for ((...))；不要用 seq（BusyBox 对 hex 支持不一致）
* 若 shell 不是 bash，改用十进制地址：
    0x08000300=134218496  0x080003FC=134218748
    0x0805C000=134348800  0x0805C0F0=134349040
    0x08068000=134397952  0x080680F0=134398192
    0x080B8000=134430720  0x080B80F0=134430960
    0x0800046C=134217836
