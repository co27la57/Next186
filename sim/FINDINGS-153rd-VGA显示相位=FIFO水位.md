# FINDINGS-153rd — VGA 显示相位 = FIFO 水位（文本"顶部缺 3 排像素" / 图形撕裂乱跳的根因）

日期：2026-10-12
现象来源：用户上板报告 + 猴岛小英雄开场照片（暂停后的稳定画面）+ 用户提供的原版开场图（判方向用）

## 1. 方向判定（照片 vs 原版图）

**结论：显示内容整体被向左平移约 50–90 个源列（一行 320 列），并带一条竖直"缝合线"；缝的右边出现的是这一行的开头（回绕）。**

三个独立证据（都不依赖动画状态）：

1. **底部版权串被切成两段**（`sim/ANALYSIS-153rd/ph_bottom2.png`）：
   照片左侧是 `LucasArts Entertainment Company.`（串的**中段**），
   **缝右侧是 `TM & (c)`（串的**开头**）**。
   ⇒ 这一段的内容是"从源列 a 开始 → 到行尾 → 回绕到列 0"，即**左移**。
   原版图 `ref_title_screen.png` 可确认 `TM & (c) 1990 …` 才是串首。
2. **第二行 `All Rights Reserved.`**：照片中的起点比原版图左移约 **50 列**
   （换算：照片有效区 ≈1870px / 640 显示像素 = 5.84 px/源列）。
3. **缝合线位置** ≈ 照片 x=1380/1920 ⇒ 约有效宽度的 **72%**。
   按"行 = a..319 再回绕 0..a"的模型 ⇒ a ≈ 0.72×320 ≈ **230** ⇒ 左移 ≈ **90 列**。

> 两条独立估计给出 50–90 列，量级一致（差异来自动画状态/照片透视）。**方向是确定的：向左**。
> 对照 `crop_seam_right.png` 可直接看到：缝两侧的云、山脊轮廓整体错开一个固定量，缝右侧是"另一段"内容。

## 2. 根因：显示侧与取指侧之间**没有任何帧/行级同步**

### 2.1 结构事实（代码位置）

| 侧 | 时钟 | 关键信号 | 行为 |
|---|---|---|---|
| 显示 | clk_25 | `hcount/vcount`(vga.v:VGA_SG) → `vrden`(ddr_186.v:259) | 文本每 16 像素弹 1 个 32-bit 读字（`&hcount_pan[3:0]`），13h 每 8 像素弹 1 个 |
| 取指 | clk_sdr | `vga_ddr_row_count/vga_lnbytecount/vga_repln_count/vga_ddr_row_col` → `sdraddr`(ddr_186.v:1179) | 每行发 6 次(文本)/11 次(13h) VGA 读，每次推进 8 个"单位" |
| 缓冲 | 双时钟 | `fifo`(ddr_186.v:581，16bit 写 / 32bit 读) | `s_prog_full <= fifo_wr_used_words > 350` **只是限流**，不是同步 |

- 两侧**速率相同**（文本每行各 48 读字、13h 各 88 读字）⇒ 长期不回卷；
- 但**显示帧起点落在流的哪个位置，完全由那一刻的水位决定**：
  `Δ = L(读字数) − c'(取指侧行相位)`，Δ 就是"屏幕上第 k 行其实显示的是帧缓冲第 k+Δ/行长 行"。

### 2.2 Δ 非行长整数倍时出现的现象（与用户报告逐条对上）

- **文本**：每个字符行在流里是 16 个**拷贝**（每拷贝 48 读字，同一行重取 16 次）。
  Δ = 3 拷贝时 ⇒ 每行**顶部 3 排像素**显示的是**相邻行**的字符；
  而屏幕第一行那 3 排取自"上一帧的最后一行"（多为空白）⇒ 看起来就是
  **"第一行顶部缺 3 排像素"**，且因为 Δ ≡ 0 (mod 48) ⇒ **没有水平缝**（文本是可读的）✅ 与报告完全一致。
- **13h**：行长 88 读字，Δ mod 88 = 13~22 ≠ 0 ⇒ **行内出现水平错位（缝合线）+ 整行左移**，
  左移量 = 4×Δ 列 ⇒ 52~90 列 ✅ 与 §1 的照片测量一致。

### 2.3 为什么水位会漂（= 为什么"乱跳/闪烁"）

水位不是被钉死的，而是"DDR 带宽平衡"决定的，而 CPU（cache 填充/写回）与 VGA 抢同一条 DDR：

- 取指侧现在**白白浪费一半 DDR 读带宽**（见 §3）⇒ 水位长期偏低、在门限下方漂 ⇒ **Δ 逐帧变化** ⇒ 乱跳；
- **13h 时 CPU 写显存最凶** ⇒ 水位漂得最厉害（猴岛开场剧烈闪烁）；**按空格暂停后 CPU 不再写显存** ⇒ 水位稳定 ⇒ 画面稳定（只剩一个固定的 Δ ⇒ 照片里那条缝）✅
- 偶尔闪烁 = 水位瞬间掉到 0 附近 ⇒ 显示弹到 stale 数据（重复一小段）✅

### 2.4 顺带解释：122nd 为什么"治了旋转、留下乱跳"

122nd 把行序复位从取指侧 `s_vga_endframe`（自洽、周期恒定）改成显示侧 `vcount == 10'd0`，
**但该复位被包在 `if(s_vga_endscanline)` 里**（ddr_186.v:1247/1285）：
能否在这一窗内被取指侧的行末命中，取决于当时的 DDR 延迟 ⇒ **取指帧边界变成竞态** ⇒
每帧的 Δ 可能 ±1 扫描行地跳 ⇒ 相位不再是一个可标定的常量 ⇒ 后面所有"-8 / -448 / -488"都只能瞎撞。

## 3. 本次已应用修复：153rd（零风险、**功能等价**）

文件 `top_zynq7010.v`：

```diff
- main_arlen   <= 8'd15;
+ main_arlen   <= (ram_cmd == 2'b10) ? 8'd7 : 8'd15;   // VGA 读 8 拍；cache 填充仍 16 拍
```

**为什么 8 拍是精确值（不是拍脑袋）**：
`ddr_186.v:1234` 在 VGA ack 时 `col_counter <= {1'b0, max_read, 1'b1} = 15`，
而每个被接受的半字（`sys_rd_data_valid`）让它减 1；到**第 17 个半字**时 `col_counter[4] = 1`，
把 `.wrreq(... && !col_counter[4])` 拉低 ⇒ **每个 VGA 事务只收下 16 个半字 = 32 字节 = 8 个 32-bit 字 = 8 拍**。

⇒ 8 拍与 16 拍**进 FIFO 的数据完全相同**（都是前 32 字节），
但 16 拍会把 64B 里的后 32B **白取**（VGA 的 DDR 读流量翻倍浪费）⇒ FIFO 回填速度减半 ⇒ 水位被钉在门限下方来回漂。

- 预期：水位抬到门限附近并被钉住 ⇒ **乱跳/闪烁显著减轻**；Δ 变成"接近常量"，残余错位从"乱跳"退回"静态、可标定"。
- 回退：`cp sim/run/top_zynq7010.v.preVga8Beat top_zynq7010.v`
- ⚠ 2026-09-27 的 103rd 曾上过"**4 拍**"版：那个数值来自台架把接受上限建模成 **8 个半字**（RTL 实际是 16 个半字）⇒ 4 拍会**少供一半数据**。正确值是 **8 拍**。
- cache 填充（cmd=11）保持 16 拍 = 64B = 一整条 cache 行，**未动**。
- Verilator lint 通过（仅 baseline 的 MODMISSING）。

## 4. 根治方案（建议下一步，未应用）：每帧相位重同步（放在 vblank 里）

**目标**：让"显示帧第一拍弹出的字" = "取指侧第 0 行第 0 个字"。
一旦成立，映射就与水位无关（水位只决定延迟余量）⇒ 缝、缺行、乱跳一起消失。

**做法（全部落在 ddr_186.v）**：

1. **触发**：clk_25 域在 vblank 起点（`vcount == 10'd480`）发 1 拍脉冲，2FF 同步进 clk_sdr。
   （放在 vblank 起点而不是 `vcount==0`：显示此期间不弹字，重同步不会撕画面，且留 ~39 行 ≈1.2ms 预取时间。）
2. **clk_sdr 侧小 FSM（≈24 拍）**：
   - ① 把 `cntrl0_user_command_register` 压成 `2'b00`（停发新事务）；
   - ② **关掉 FIFO 写**（丢弃在途 burst 的余波——否则它会落进刚清空的 FIFO，把起点顶偏）；
   - ③ 拉高 `fifo_rst` ≥16 拍（Xilinx FIFO 的 rst 是异步的，要求 ≥3 个**慢时钟** clk_25 周期）；
   - ④ 同步清零取指计数器：`vga_ddr_row_col <= 帧基址`、`vga_lnbytecount <= 0`、
     `vga_repln_count <= 0`、`vga_ddr_row_count <= 0`、`s_vga_endscanline <= 0`；
   - ⑤ 放开；取指从行 0 重新灌，显示在 `vcount==0` 起接着弹 ⇒ 第一拍弹到的就是行 0 的字。
3. **配套常量**：把 `sdraddr` 里的 `- 5'd8` 改成 `- 5'd0`
   （-8 是当年为补**同类相位误差**留下的常量；重同步后起点即行首字，不再需要。
   若文本出现 16 字符偏移，再一次性回退成 -8 标定即可。`1'b0` 末位**严格不动**）。
4. **可删**：122nd 的 `if(vcount == 10'd0)` 复位被 480 处的重同步取代。
5. **失败模式变化**：以后即便 DDR 被抢，表现只是"某段内容重复/stale"，**下一帧自动校正**，
   而不是相位永久漂移。

**风险点**：① 在途 burst 必须同时被丢弃＋停发，否则起点被污染；② FIFO rst 的异步宽度要够；
③ 首次上板可能需要把 `-k` 在 {0, 8} 里二选一（一次性标定，不再是随机量）。

## 5. 验证判据（ILA / 探针）

1. **水位稳定性（最直接）**：探 `fifo_wr_used_words`(9bit) + 一个"帧起点"标记
   （clk_25 域 `vcount==0` 打一拍，同步到 clk_sdr）。判据：**帧起点那一刻的水位逐帧基本不变**（±一个 burst = 16）。
   若仍在漂 ⇒ 取指侧带宽/相位还在漂，需做 §4。
2. **相位直接读数**：新增 `dbg_vga_repln_at_fs <= vga_repln_count`、`dbg_vga_lnb_at_fs <= vga_lnbytecount`
   （在帧起点锁存）⇒ 这两个数就是"显示帧起点落在取指侧行内的第几个拷贝/第几个单位"，即 Δ。
3. **免探针判据**：文本第一行是否不再缺顶部 3 排像素；13h 那条竖缝是否消失且不再漂。
