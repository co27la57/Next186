# 下板测试单 v4b：冻结探针（commit `180d84e`）

---

## 0. 为什么必须再下一轮

v4（`f64dab6`）板上读数：`dbg_rd_reg = 0x021`、`dbg_wb_reg = 0x020`
⇒ 写回 idx=2 **数据高半字节 = 1**、填充 idx=2 **数据高半字节 = 0**（都应为 2）。

**但这个读数不能用** —— v4 的锁存是"最新覆盖"，而：

- **自测在启动早期跑**（挂在 `0x002E`）；
- **SD 阶段在后面也会写同一个缓冲区**（`F000:0000` = tag 0x1E0）；
- **`dbg_dbg2 = 0x9576`（非 0）恰好证明 SD 阶段跑到了算 8KB 校验和那一步** ——
  而算校验和的前提就是 8KB 已经被读出来并**写进了这个缓冲区**。

⇒ **`dbg_dbg2 ≠ 0` 不能排除 SD 阶段事件，恰恰相反：它证明 SD 阶段确实动过同一个缓冲区**
⇒ v4 抓到的极可能是 **SD 阶段**的写回/填充，那两个半字节（1 和 0）只是"SD 数据"，对我们的问题无意义。

## 1. v4b 做了什么

**在 CPU 写端口 `0x00E5`（自测上报那一刻）把两个锁存器冻结。**

- 平时照旧在**非探针**的暂存寄存器（`dbg_v4_wb_live` / `dbg_v4_rd_live`）里跟踪最新事件；
- 检测 `IORQ & CPU_CE & WR & (PORT_ADDR==0x00E5)`（clk_cpu 域），经 2 级同步后在 clk_sdr 域
  **快照**进 `dbg_rd_reg` / `dbg_wb_reg`。

BIOS 自测的顺序是：`mov ah,[di]`（读 0x80 → **line 2 的填充就在这一步**）→ `jmp 0x3d3`
→ `out dx,ax`(0xE4) → `out dx,al`(0xE5)。
⇒ **冻结时刻正好在"读 0x80 的填充"之后** ⇒ 抓到的填充就是服务那次读的那一次 ✓，
写回就是自测期间 line 2 的那一次 ✓。

**不新增探针信号 ⇒ 不用重建 Set Up Debug**（仍是 36 个 / 265 bit）。

## 2. 要读什么

| 信号 | 正确时应为 | 说明 |
|---|---|---|
| **`dbg_rd_reg[3:0]`** | **`2`** | 自测期间写回 line 2 送出的数据高半字节 |
| **`dbg_rd_reg[8:4]`** | `2` | 该写回属于的行 |
| **`dbg_wb_reg[3:0]`** | **`2`** | 服务"读 0x80"那次填充拿到的数据高半字节 |
| **`dbg_wb_reg[8:4]`** | `2` | 该填充属于的行 |
| `dbg_dbg4` / `dbg_dbg5` | `0x6010` / `0xA0` | 确认跑上了、症状还在 |
| **`dbg_bufwb_a[14:0]`** | 自测期间最后一次缓冲行写回的 hiaddr | 上轮读到 `0x3c06` = **index 6** —— 但那也可能是 SD 阶段的值，本轮已一并冻结 |
| **`dbg_bufwb_n[7:0]`** | 自测期间的缓冲行写回次数 | 上轮 `0xFF`（饱和）= SD 阶段累计；本轮冻结后应是个小数字 |

> `dbg_bufwb_a` 是关键线索：若自测期间最后一次缓冲行写回是 **index 6**，而读 0x80（line 2）得到 W(6)，
> 那就说明"**line 6 的写回写到了 line 2 的地址**"。两者已和 v4 数据锁存在**同一个 0x00E5 事件**上冻结。

**判据**：低半字节 == 行号 ⇒ 自己行的数据；**不等 ⇒ 拿到了别行的数据**。

台架已用 `inject_fill_shift` 注入验证过：`inject=4` → `fill{idx=02 nib=6}`（正是 +4 的签名），
写回侧始终 `nib=2`（能分开两侧）。

## 3. 判读

| 观测 | 结论 | 下一步 |
|---|---|---|
| 写回 `nib != 2` | 写回送出了别行的数据（地址对、数据错）⇒ **DDR 里就是错的** | 查写回读的 BRAM 端口 A 地址（`wb_way`/`wb_hiaddr`/`word_a`）|
