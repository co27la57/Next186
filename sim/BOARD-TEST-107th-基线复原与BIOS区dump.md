## 1. ★ 纠正：BIOS 映像载入的地址是 **F000:E000**，不是我之前说的 F000:0000

用早期那次"走到按键等待"的整段 F 窗口 dump（`sim/run/fseg.bin`）与卡上 8KB（`card8k.bin`）逐字节比：

```
F 窗口 0xE000 处的 8KB  vs  card8k.bin :  3 / 8192 字节不同
   差异位置（映像内偏移）：0x1605(00→81)、0x1606(00→E0)、0x1608(00→20)
   → 其余 8189 字节完全相同
```
⇒ **卡上那 8KB BIOS 映像被放在 F000:E000（物理 `0x080F_E000`）**，只被 BIOS 自己在运行时改写了 3 个字节
（0x1600 附近是它的变量/指针区）。

**为什么是 0xE000**：8086 复位后从 `F000:FFF0` 取第一条指令 ⇒ BIOS 必须在 **F 段顶部**，
所以作者把 8KB 映像放在 F000:E000..F000:FFFF（正好 8KB）✓。F000:0000..DFFF 是 BIOS 的工作区/表/SD 缓冲。

**顺带纠正两个错地址**（我之前给过错的）：
| 目标 | 物理地址 | `dd bs=4096 skip=` |
|---|---|---|
| **BIOS 映像 8KB（F000:E000）** | **`0x080F_E000`** | **33022** |
| F 段低 56KB（工作区/SD 缓冲） | `0x080F_0000` | 33008 |

（此前说过的 `skip=32928` 是错的，那指向 `0x080A_0000`。旧笔记里的 `0x0815_xxxx` 也是错的。）

## 2. dump 命令（板端，**纯 devmem** —— dd 在你板上不可用）

### ① 先做"路标自检"（一条命令，21 行输出，最快）

```sh
for a in 0x080FE000 0x080FE004 0x080FE008 0x080FE00C 0x080FE040 0x080FE044 \
         0x080FE100 0x080FE400 0x080FE800 0x080FEC00 0x080FF000 0x080FF400 \
         0x080FF600 0x080FF604 0x080FF800 0x080FFC00 0x080FFCC0 0x080FFCD8 \
         0x080FFE00 0x080FFF00 0x080FFFF0 ; do
  printf "%08x: " $a; devmem $a 32
done
```

对照值（卡上 8KB 的原始内容，绝对地址 → 期望值）：

| 地址 | 期望值 | 含义 |
|---|---|---|
| `0x080FE000` | `0x7478654E` | "Next"（映像头）|
| `0x080FE004` | `0x20363831` | "186 " |
| `0x080FE008` | `0x7470654E` | "Nept" |
| `0x080FE00C` | `0x204F4E55` | "UNO " |
| `0x080FE040` | `0x0A0D6472` | "rd\r\n" |
| `0x080FE044` | `0x32535000` | "PS2"(检测串附近) |
| `0x080FE100` | `0xF4210060` | 代码区 |
| `0x080FE400` | `0xEB01CA80` | 代码区 |
| `0x080FE800` | `0xEC75083C` | 代码区 |
| `0x080FEC00` | `0x03D6031C` | 代码区 |
| `0x080FF000` | `0xA1508575` | 代码区 |
| `0x080FF400` | `0xF7009726` | 代码区 |
| `0x080FF600` | `0x0526FF2E` | 代码区 |
| **`0x080FF604`** | `0x000000F6` **或** `0x00E081F6` | 这两个值都正常：0x1605/0x1606/0x1608 会被 BIOS 运行时改写 |
| `0x080FF800` | `0xE81F16FC` | 代码区 |

| `0x080FFCC0` | `0x3C006800` | 键盘扫描码表 |

| `0x080FFE00` | `0x48009D00` | 键盘表 |
| `0x080FFF00` | `0x00000000` | 填充区（本来就是 0）|
| **`0x080FFFF0`** | **`0x00E05BEA`** | **复位向量** = `EA 5B E0 00 E0` = `jmp far E000:005B` —— **最强单点指标** |

### ② 整段 8KB 全 dump 到文件（2048 行，写法和你以前 64KB 那次一样）

```sh
b=$((0x080FE000)); i=0
while [ $i -lt 8192 ]; do printf "%08x: " $((b+i)); devmem $((b+i)) 32; i=$((i+4)); done > /tmp/bios8k.txt
wc -l /tmp/bios8k.txt          # 应为 2048
head -2 /tmp/bios8k.txt
tail -2 /tmp/bios8k.txt
```

把 `/tmp/bios8k.txt` 拷到 PC 发我（或直接贴），我做**逐字节比对**。

### ③ 可选：若板上有 `md5sum`

```sh
md5sum /tmp/bios8k.txt
# 映像完好（= 卡上 8KB 原样）时这份文本的 md5 应为：
#   91b729ac4dc373f560066fc6506b5473
# 注意：若 0x1605/0x1606/0x1608 已被运行时改写，md5 会不同，这不代表损坏 —— 以 ① 的路标和②的全字节比对为准。
```

## 3. 判据

| dump 结果（`0x080F_E000` 起 8KB） | 结论 |
|---|---|
| 与 `card8k.bin` 完全相同，或只差约 3 字节（含 0x1605/0x1606/0x1608） | **BIOS 映像完好** ⇒ 内存/取指没问题，问题只在显示侧 |
| 大片不同（几十~几百字节以上）或含乱码段落 | **BIOS 映像被打坏** ⇒ 是内存/缓存路径的问题，需按差异形态定位 |
| 全 0 / 全 FF | **映像根本没载入** ⇒ SD 加载阶段失败 |

## 4. 顺便修正对 ILA 那两个读数的解释

| 读数 | 解释 |
|---|---|
| `dbg_cpu_laddr = 0x0FFCD8` | F000:FCD8 = **BIOS 映像内偏移 0x1CD8**（映像基址 0xE000）⇒ 这是 **BIOS 自己的代码/表区**，说明 **CPU 正常地在执行 BIOS**（同上次"走到按键等待"时的形态一致），不是跑飞 |
| `dbg_cpu_lport = 0x0040` | 8253 定时器通道 0（延时/节拍）—— BIOS 常规动作 |
| `dbg_vga_13 = 3`、`text = 3` | 模式寄存器被软件写过（含 13h）⇒ BIOS **做过显示模式设置**；而**模式设置会清显存** ⇒ `0x08068000` 文本页读全 0 是**设计使然**，不一定代表内存故障 |
| 屏幕"乱码垃圾" | 与 §1 的 `col_leftover=7`（写门多开 8 拍、cache 数据漏进 VGA FIFO）一致 |

⇒ 所以"CPU 跑飞/BIOS 损坏"这条**还没有证据**，先用 §2 的 dump 定案，再看要不要上 105th′。
