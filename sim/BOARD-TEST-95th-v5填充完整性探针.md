## 0. 为什么再下一轮：v4b 的读数**不可用**

v4b 板上读数 `dbg_rd_reg = 0x022`（写回 idx2 / nib2 自洽）、`dbg_wb_reg = 0x020`（填充 idx2 / nib0）。
按决策表这本该判"填充侧"，**但那个采集门有洞**：

```verilog
end else if(dbg_fill_arm && sys_rd_data_valid) begin     // ← 没有要求 sys_cmd_ack == 2'b11
```

`sys_rd_data_valid` 对 **VGA 读（cmd `2'b10`）同样为高** —— 这正是 91st 在 RTL 里修掉的
"不认 burst 归属"漏洞，探针里原样留着。而板上 `dbg_fill_foreign = 1`
**已经证明填充窗口内确有非本 burst 的数据到达**。
⇒ `nib = 0` 极可能就是"未写过的 VGA 单元 = `0x0000`"，**不能作为"填充读错地址"的证据**。

## 1. v5 改了什么

**(a) 补洞**：两处采集都门控到本笔 burst
```verilog
end else if(dbg_fill_arm && sys_rd_data_valid && (sys_cmd_ack == 2'b11)) begin   // 填充
end else if(dbg_wb_arm   && sys_wr_data_valid && (sys_cmd_ack == 2'b01)) begin   // 写回
```

**(b) 删掉三个已饱和的废探针，换成五个新探针**（`dbg_wb_or[31:0]` / `dbg_rd_or[15:0]` /
`dbg_vga_or[15:0]` 板上实测全 `FFFFFFFF`/`FFFF`，零信息量）：

| 探针 | 宽 | 含义 | 期望（line 2，图案 `byte@m=(m>>2)&0xFF`） |
|---|---|---|---|
| `dbg_fill_w0[15:0]` | 16 | 本笔填充**自己的 burst** 送出的**首字** | `0x2020`（+4 行 ⇒ `0x6060`） |
| `dbg_fill_wl[15:0]` | 16 | 同上，**末字**（第 32 拍） | `0x2F2F`（+4 行 ⇒ `0x6F6F`） |
| `dbg_fill_n[5:0]` | 6 | 窗口内**自己的** burst 的 valid 脉冲数 | `32`（**`64` ⇒ 本笔被发了两次 burst**；`<32` ⇒ 未跑满） |
| `dbg_fill_x[5:0]` | 6 | 窗口内**外来**（非 `2'b11`）valid 脉冲数 | `0` |
| `dbg_fill_full` | 1 | 自己的 burst 是否跑满 32 拍 | `1` |

窗口：在"缓冲行 idx2 的填充 ack 上升沿"打开，在（ack 离开 `2'b11` 且 `ddr_rd` 已落）时关闭。
**全部在 CPU 写 `0x00E5` 那一刻冻结**（与 v4b 同一事件）——不冻结会被 SD 阶段覆盖。

探针预算：**38 信号 / 246 bit**（原 36 / 265，预算 300）。
校验：CRLF 1376/0；begin/end 51/51；每个 scratch 名恰好声明一次。

| **`dbg_fill_wl`** | **`0x0C00`** | 填充末字 = `0x0C00`（期望 `0x2F2F`）|

⇒ **填充通路无罪**（完整、没被 VGA 插队），**但它从 DDR 拿回的数据就不是 line 2 的图案**；
且 `w0=0x0000` 与 CPU 的 `[0x80]=0x00` **吻合** ⇒ 两条独立证据互证。
⇒ **定罪对象 = DDR 在 line 2 地址（`0x0815_0080`）上的内容。**

`0x0C00` 的来源已排除两项：**不是自测图案**（图案里 `(0x00,0x0C)` 相邻对不可能出现，已验算）、
**不是 BIOS**（`sim/tools/find_bios_window.py` 全 1024 字节搜过，`bios_rom` 256 项里
**没有**任何 `(0x00,0x0C)` 字节对，也没有末半字 = `0x0C00` 的 64B 窗口）。
`0x0C00` 是教科书级 **VGA 文本单元**（字符 `0x00` + 属性 `0x0C`）。

同时 `dbg_rd_reg = 0x022` 证明**确有一次** line 2 的真实 AXI 写 burst、数据还是 line 2 自己的。
**这两件事同时成立只有两种解释**：
- **(a)** 写回落到了别的地址（数据对、地址错）；
- **(b)** 填充在写回落地**之前**就读了 DDR（顺序错）⇒ cache 装进了旧 DDR 内容，之后写回才落地。

### ⚠⚠ v6 抽头修正（第二版，**下板用这一版**）
第一版 v6 的页号取 `sdraddr[23:15]` 的 **2 级延迟** —— **错了一拍**。正确推导：
FSM 在采样沿 k+1 读 `sdraddr(k)`，而 `dbg_pg_d1(k+1) = sdraddr(k)` ⇒ **正确抽头是 d1**。
用 d2 会恰好捕到"上一行的页"⇒ 板上读到 `0x00F` 很可能只是这个假象
（写回的 victim 常是 BIOS 行 ⇒ 上一拍页号 = BIOS 页）。
`pmis` 拿 d2 与当前 `memmap_mux` 比（差 2 拍）⇒ hiaddr 一动就误报 ⇒ 板上饱和到 `0xF`。

**修正**：抽头改 d1；`pmis_r/w` 由 4 位加宽到 6 位（4 位在板上已饱和）。
预算 **43 信号 / 292 bit**；CRLF 1434/0；begin/end 57/57。

### ★ `seg_map` 的映射表（`cache_controller.v:1169`）——判读页号的依据
```
map[15] = 21 (0x15)  ← tag[9:5]=0x0F（缓冲区 tag 0x1E0..0x1E7）→ 物理 0x0815_xxxx
map[31] = 15 (0x0F)  ← tag[9:5]=0x1F（BIOS/HMA tag 0x1F8..0x1FF）→ 物理 0x080F_xxxx
```
★ `map[16..31]` **不可被 BIOS 改写**（`map[{1'b0,cpuaddr}]`，cpuaddr 只有 4 位 ⇒ 只能写 map[0..15]）
⇒ `map[31]=15` 是**永久**的。⇒ **BIOS 区实际在 `0x080F_FC00`，不是旧笔记写的 `0x0815_FC00`**。
⇒ **板上读到页 `0x00F` = BIOS/HMA 区的页**；`0x006` 才是 VRAM（map[11]=6）。

### ★ 板/台架页号差异的真相：**是 BIOS 写的，不是 bug**
BIOS `0x0015..0x0017`：`mov al,0xf / out 0x8f,ax` ⇒ **`map[15] = 0x0F`**。
⇒ 缓冲区 (tag[9:5]=0x0F) 在板上的物理页 = **0x0F = `0x080F_xxxx`**（F 段 1:1），**完全正确**。
⇒ **台架的 seg_map 没人跑这段初始化，永远停在初值 `map[15]=21(0x15)`** ⇒ 台架所有地址都在
`0x0815_xxxx`。**这就是台架复现不了的保真度缺口之一**（顺带：旧笔记"BIOS 在 0x0815_FC00"是错的，
正确是 `0x080F_FC00`，因为 `map[31]=15` 且 map[16..31] 不可被 BIOS 改写）。

### ⇒ 收敛后的状态
写回：数据对、地址对（页 0x0F + index 2）。填充：数据错、页对。`pmis=0/0` ⇒ 页从不过期。
**但 `dbg_pmis` 只比较了 `sdraddr[23:15]`（页）—— 没比较 `sdraddr[14:5]`（{tag[4:0], index}）。**
如果 `cache_hi_addr` 在采样窗口内换成了**同一页里的另一行**（缓冲区内部 thrash 最常见），
`pmis` 照样是 0，而填充就会读到**缓冲区里另一行的地址** ⇒ **这正是 +N 行位移的机制**。

## 5. ⚠ 台架顺带跑出的一个反证（与板上症状不同的第二种形态）

已知损坏配置 `1 0 0 0 4 3 0 3 8 0 6 40 400`（`fix_re=0`，4:1）：
```
buffer lines mismatching in DDR: 0 / 16        <- DDR 完好
mismatched bytes: 192 / 1024  first at 0x080: got 0x2C expect 0x20
```
`0x2C` 与 `0x20` **同属 line 2**（`0x20..0x2F`）⇒ 这是**行内字相位错位**（同行的第 3 个字跑到了第 0 个字），
**不是跨行**。⇒ 台架能复现"读侧 + 行内相位"这一类损坏；而板上是**跨行 +4/+5 与 0x00**，
是另一种形态 ⇒ 两者机制不同，**不要把台架的结论直接套到板上**。
