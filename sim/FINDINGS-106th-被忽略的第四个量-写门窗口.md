# 106th 复盘：被忽略的"第四个量"——FIFO 写门窗口 `col_counter`

日期：2026-09-27
触发：105th 下板后**屏幕全是乱码垃圾**、`dump 0x08068000 起的 VRAM 全是 0`、`dbg_cpu_ios=05`
当前工作树：**已恢复到"能显示但每 8 字符重复"那一版**（`ddr_186.v` / `top_zynq7010.v` 与 `pre105th` 逐字一致）

## 1. 先做你要的对比：各版本的四个量（半字口径）

VGA 读数有**四个**互相咬合的量（前三个在半字口径下应该相等）：

| 版本 | ① 地址步进 | ② 写门窗口 `col_counter` | ③ 一次读交付 | ④ 行结束判据 |
|---|---|---|---|---|
| **作者原版**（单位 4B） | 8 单位 = 32B = **16 半字** | 装载 15 ⇒ 开 **16 半字** | cmd10 = 32B = **16 半字** | `[7:3]==6`，每读 +1 ✓ |
| git HEAD（会话起点） | 同 pre100C | 同 pre100C | 16 拍 = **32 半字** | 6 |
| **pre100C（能显示+重复）** | 8 单位 = 16B = **8 半字** | 装载 15 ⇒ 开 **16 半字** | 16 拍 = **32 半字** | 6 |
| 100th-C / 104th | 16 单位 = 32B = 16 半字 | 15 ⇒ 16 | 64B / 32B | 12（判据被跳格破坏 ⇒ 黑屏） |
| **105th（本轮回退掉）** | 8 单位 = 16B = **8 半字** ✓ | **15 ⇒ 16 半字** ✗ | 4 拍 = 16B = **8 半字** ✓ | 12 ✓ |
| **105th′（修正方案）** | 8 半字 ✓ | **装载 max_read ⇒ 8 半字** ✓ | 8 半字 ✓ | 12 ✓ |

**⇒ 作者的不变量是"① = ② = ③"（三个量在半字口径下同一个数）。**
移植版把 ③（交付）和 ① 调对了，**② 一直没动** —— 这就是被忽略的地方。

## 2. 台架量化证据（新增 `col_leftover` 观测：上一笔 VGA 读结束时 `col_counter` 的余量）

```
能显示的那一版 (16拍交付 + 窗口16): accepted=16  col_leftover=15   ← 中途经过"关闭"(bit4=1)
105th          ( 4拍交付 + 窗口16): accepted= 8  col_leftover= 7   ❌ 写门还开着 8 拍
105th′         ( 4拍交付 + 窗口 8): accepted= 8  col_leftover=31   ✅ 结束时正好关闭
```
`col_leftover` 的 bit4 = 1 表示**写门已关**。所以：
- 105th：每笔 VGA 读之后，写门仍开着 **8 拍**；
- 这 8 拍里若有 `!crw && sys_rd_data_valid`（典型情形：**一个 VGA ack 落进 cache burst 内部**，
  此后 cache 剩余拍满足 `!crw`）⇒ **cache 数据被写进 VGA FIFO** ⇒ 屏幕乱码垃圾；
- 105th′ 把这 8 拍关掉 ⇒ 窗口 = 交付 = 步进 ⇒ 回到作者的不变量。

**为什么台架之前看不出来**：台架的 VGA/cache 交错从没让一个 cache valid 落进那 8 拍窗口里，
所以自测 `0/1024 PASS`、字符流也单调 —— **又一次"没有对应模型就看不见"**。
这次不是靠推理，而是把窗口余量本身变成了可观测量（`col_leftover`）。

## 5. 上板前还该查的一件事（CPU/内存侧，与 §4 无关）

105th 板上 `dump 0x08068000 起全 0` + `dbg_cpu_ios=05`（只有 5 次 I/O）说明 CPU **没走到打印阶段**。
两种可能，用一次 dump 就能分开：

1. **CPU 真卡在极早期**（BIOS 区被破坏 / 取指失败）⇒
   请 dump **BIOS 区 `0x080F0000..0x080F1FFF`（8KB）**，与卡上 8KB 映像逐字节比：
   - 完全一致 ⇒ 内存搬运没问题，CPU 是别的原因卡住（把 `dbg_cpu_ios` 隔几秒连读两次，看它是否在涨）；
   - 有差异 ⇒ **是内存/取指被破坏** ⇒ 那是 AXI 侧的另一条线（例如某笔 cache 填充只填了一半），
     我们按"哪个地址、什么形态"再定位。
2. **只是采样时刻早**（ILA 触发在早期、dump 也在早期）⇒ 连读两次 `dbg_cpu_ios`/`laddr` 即可判断。

> 注：这条与 §4 的写门窗口是**两个独立的量**，别混。先把 §4 修好（内容管线），再用 §5 的 dump 定 CPU 侧。
