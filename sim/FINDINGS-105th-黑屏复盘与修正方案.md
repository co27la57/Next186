# 105th 复盘：为什么"黑屏"、为什么台架看不见，以及重排后的方案

日期：2026-09-27
上一版（104th）结果：**显示器提示"非最佳模式"（= 同步在）→ 黑屏；`dbg_font_*` 全 0**
当前工作树状态：**已回退到"能显示但每 8 字符重复"那一版**（与改动前逐字一致，见 §3）

---

## 1. 为什么黑屏 —— 我这次改动的**结构性错误**（已用算术证明）

作者的行结束判据是**等号**：

```verilog
end else s_vga_endscanline <= (vga_lnbytecount[7:3] == vga_lnend);
```

等号成立的前提是：**`[7:3]` 每读至多 +1**，也就是 **步进 ≤ 8 单位**。
作者的设计里步进 = `max_read+1 ∈ 1..8` ⇒ `[7:3]` 每读 +0 或 +1 ⇒ **必然依次经过每个整数 ⇒ 等号必中**。

我在 104th 把步进改成 `2*(max_read+1) ∈ 2..16`：

| 情况 | 行内 `vga_lnbytecount` 最大值 | 上界 `8*(lnend+1)` | 结果 |
|---|---|---|---|
| 步进恒 16（台架里就是这一种） | 96 | 104 | ✅ 受控（所以台架看着正常） |
| **混入一次步进 8**（钳位/脱栅格） | **240** | 104 | ❌ **失控** |

现场（逐读模拟）：
```
读 58: lnbytecount=88  [7:3]=11
读 59: lnbytecount=104 [7:3]=13   ← 12 被跳过！
此后等号永不成立 ⇒ lnbytecount 一路加到 0xFF 回绕 ⇒ 显示地址跑出文本区 ⇒ 全黑
```
**这正是"非最佳模式（同步在）+ 全黑"的形状**：`FifoStart` 早已置位 ⇒ 行场同步照旧；坏的只是取数地址。

**两次独立实验的相关性**（很强的经验支持）：
- 步进翻倍 → 黑屏：**100th-C**（曾把 `vga_lnbytecount` 步进翻倍）与 **104th** —— 两次症状完全相同（非最佳模式 + 全黑）；
- 步进不翻倍 → 能显示（哪怕内容有重复）：**当前回退版**、以及此前所有版本。

**更深一层的结构性冲突**（这解释了为什么我"顺手把步进翻倍"是错的思路）：
移植版 sdraddr 单位 = **2 字节**，而作者要求"一次读 = 8 单位 = **32 字节**"。要两者同时成立，
单位必须是 4 字节 —— 但**移植版做不到**：4 字节单位下孔径基址 `2^17×4B = 512KB`
已经**超过**移植版 VRAM 的字节地址 `0x068000 = 416KB`，地址根本落不进去
（移植版的 64KB 页映射、VRAM 页 6 = 384KB 是不可动的，BIOS 按它写）。
⇒ **"步进 = 32 字节"在移植版里必然要求 `[7:3]` 每读 +2 ⇒ 等号判据必然被破坏。**
⇒ 所以正解不是改步进，而是**让每次读的交付量去匹配作者的步进**（= 16 字节 = 4 拍突发）。

## 2. 为什么台架看不见这个失效（又一次"没模型就不能声称验证"）

台架里 VGA 地址恒定落在 **16 单位栅格**上（我甚至算过：`&sdraddr[7:3]` 需要
`sdraddr mod 256 ∈ 248..255`，而 248 不是 16 的倍数 ⇒ 钳位不触发 ⇒ `max_read` 恒为 7）
⇒ 台架只跑得出"步进恒 16"那一列 **✅ 受控**，永远跑不出"混入步进 8"那一列 **❌ 失控**。
而板上只要有一次读的 `max_read ≠ 7`（钳位、或采样瞬间取到 cache 地址而脱栅格），就会翻车。

**⇒ 台架的 `fix_100` 只是"几何/流量"模型，它不建模"判据的等号鲁棒性"。这条教训记入规矩：
凡改动会碰到某个"等号/边界判据"的输入量时，必须先在台架里把该判据的鲁棒性单列一条判据。**

## 4. 你给的 CPU 读数说明了什么（CPU 侧没问题）

| 读数 | 解释 |
|---|---|
| `dbg_cpu_laddr = 0x0FFCD8` | seg_map 页 = ADDR[19:16] = 0xF ⇒ 物理 `0x080F_FCD8` = F000:FCD8。**反汇编 F 段 dump 后确认：这里是键盘扫描码翻译表（数据），不是代码** ⇒ 这是**取表**的读，不是跑飞 |
| `dbg_cpu_lport = 0x0040` | **8253 定时器通道 0**（延时/节拍读取），不是 SD 口、也不是键盘口 |
| 组合含义 | CPU **活着**，正在 BIOS 的"键盘 + 定时器"路径里 —— 就是之前定位过的那条 **"No boot device available, waiting on RS232/按键"** 等待路径 |

⇒ **系统内部没坏，黑屏是纯粹的显示侧问题**（CPU 依旧走到同一处）。这也解释了为什么"同步在、内容黑"：
显示被使能了（`FifoStart` 置位），但取数地址在 §1 那个失控状态下跑出了文本区。

## 5. 重排后的方案：105th（四条约束夹出来的唯一解，**已台架验证**）

| 约束 | 内容 | 结论 |
|---|---|---|
| ① | 行结束判据是等号 ⇒ 要求 `[7:3]` 每读至多 +1 | **步进必须保持 `max_read+1`（≤8 单位）—— 一个字不改** |
| ② | 交付量必须等于推进量（否则就是"每 8 字符重复"） | 推进 8 单位 = **16 字节** ⇒ **VGA 读 AXI 突发 = 4 拍** |
| ③ | 一次扫描行要扫满整行（80 列 = 160 字节） | 每读 16 字节 ⇒ 需 12 次读 ⇒ **`vga_lnend` 文本分支 6 → 12** |
| ④ | 字符行推进要正好一行 | 160 字节 ⇒ **行步进 40 → 80 单位** |

改动清单（共 3 处）：
```
ddr_186.v        : vga_lnend 文本 6 -> 12 ;  行步进 40 -> 80
top_zynq7010.v   : main_arlen <= (ram_cmd == 2'b10) ? 8'd3 : 8'd15;   (VGA 读 4 拍)
不动：vga_lnbytecount 步进、s_vga_endscanline 判据、col_counter、FIFO 写门、所有基址常量
```
台架数据（`ddr_pipe.exe … 12 80 … fix_100=2`）：
```
AR: 8068000→8068010→…→80680b0→复位   步进 16B ✅  12 次读/行 ✅  扫过 192B ✅  基址未动 ✅
实收流: a000 a001 a002 … a00b          严格单调、无重叠 ✅
FLOW: lvl 60~364, s_prog_empty 高占比 0.14%, underruns=0 ✅
CONTROL 0x10 ✅  MEASURE 0x20 ✅  mismatched 0/1024 PASS ✅
```
与作者原版对照：**逐字节同形**（每次读 16B×12 = 192B 扫描行；行 160B），
差别只是"分成 12 笔 4 拍"而不是"6 笔 16 拍"，而且**总线流量减半**（每扫描行 384B → 192B）。

### 判据鲁棒性复核（这次专门验）
| 方案 | 步进 | 混入小步进时行内计数最大值 | 结论 |
|---|---|---|---|
| 104th | 2*(max_read+1) | **240 > 104** | ❌ 失控（黑屏） |
| **105th** | `max_read+1`（作者原文） | 96 / 99 ≤ 104 | ✅ 有界，判据必中 |
