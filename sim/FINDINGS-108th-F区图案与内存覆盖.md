# 108th：105th 那份 BIOS 区 dump 的解读 —— **F 段被"地址图案"覆盖**（不是显示问题）

日期：2026-09-27
输入：用户在 **105th 那版 bitstream** 上 dump 的 21 个路标（`0x080FE000`~`0x080FFFF0`）

---

## 1. 硬事实：F000:E000 那 8KB 里**不是 BIOS**，而是一份"地址图案"

| 地址 | 观测 | 4 字节(LE) | 与地址的关系 |
|---|---|---|---|
| `0x080FE000` | `0x05FB05E0` | `E0 05 FB 05` | `A[15:8]=E0`，`A[7:0]=00`→`05` |
| `0x080FE004` | `0x09FB05E0` | `E0 05 FB 09` | `04+5=09` |
| `0x080FE100` | `0x05FB05E1` | `E1 05 FB 05` | `A[15:8]=E1` |
| `0x080FFCC0` | `0xC5FB05FC` | `FC 05 FB C5` | `C0+5=C5` |
| `0x080FFCD8` | `0xDDFB05FC` | `FC 05 FB DD` | `D8+5=DD` |
| `0x080FFE00` | `0x05FE03FB` | `FB 03 FE 05` | 相位错开 2 字节 |
| `0x080FFFF0` | `0x05FFF3FB` | `FB F3 FF 05` | 相位错开 2 字节 |

规律：
```
低区(0xE000..0xFDFF)： 字节 = [ A[15:8], 0x05, 0xFB, (A[7:0]+5) & 0xFF ]
0xFFE00 起         ： 同一图案、相位错开 2 字节 = [ 0xFB, 0x03, A[15:8], (A[7:0]+5) ]
```
- `0x05 + 0xFB = 0x100` ⇒ 图案里成对出现 **N 与 ~N** ⇒ **典型的"计数器 + 反码"存储器测试图案**（不是代码、不是随机数据）。
- 而 **卡上 8KB 在此处应当是**：`0x080FE000 = 0x7478654E`("Next")、`0x080FE004 = 0x20363831`("186 ")、
  `0x080FFFF0 = 0x00E05BEA`（复位向量 `jmp far E000:005B`）—— **一个都不符合** ⇒ **BIOS 映像不在了**。

⇒ **结论：105th 那一次是"内存被覆盖"型故障**，F 段（含 BIOS 映像）被写进了测试图案。

---

## 2. ★ 必须纠正我上一轮的判断

我上一轮说"`laddr=0FFCD8` 落在 BIOS 表区 ⇒ CPU 正常执行、问题只在显示侧" —— **这个解释作废**。
既然该区域内容已是图案，那么 CPU 在 F000:FCD8 上读到的是**图案**（不是键盘表），
`dbg_cpu_ios=05`（只有 5 次 I/O）也说明它**很早就没在正常跑** ⇒ 那一次是**取指/内存层面的失败**，
屏幕乱码与 VRAM 全 0 都是它的后果，**不是（或不只是）显示几何的问题**。

这也与 ILA 上的 `dbg_cpu_lwr = 1`（最后一次访存是**写**）一致：**有写操作进了 F 段**。

---

## 3. 写入者是谁：两个候选，台架已否掉一个

| 候选 | 依据 | 结论 |
|---|---|---|
| **A. BIOS 自己的内存测试/POST** 扫过 F 段并把映像覆盖 | 图案是"计数器+反码"型测试图案；`lwr=1` 说明 CPU 写过 F 段；**移植特有隐患**：作者原版 BIOS 在 ROM（不可写），移植版把 BIOS 映像放在**可写 DDR**（F 段 = `map[15]=0x0F` 的同一页，和 BIOS 自检/工作区同页）⇒ 只要测试扫过这一页就会吃掉映像 | **头号嫌疑** |
| **B. 4 拍 VGA 突发诱发伪写回**（我原本担心的） | 台架实测：`fix=0` 与 `fix=2` 两种突发下 `AW=32 (spurious=0)`、`WB spurious=0`、`RD spurious=0`、`0/1024 PASS` | **不支持** ⇒ 不是我的显示改动引起的写侧故障 |

**⇒ A 是移植引入的结构性隐患**：作者把 BIOS 放在只读存储里，所以"内存测试随便扫"没问题；
移植版把 BIOS 映像放进 DDR 的可写页 ⇒ **BIOS 自己的测试就能把自己的映像覆盖** ✓
这同时**解释了你之前那一串"逐次变化"的怪现象**（前 64 字节被抹成 `92 00…`、第一片地址变 0、
同一地址不同 boot 内容不同、"SD 映像被破坏"）—— **同一个机制，每次扫到的范围/时机不同而已**。

## 4. 下一步（先查"谁写的、范围到哪"，显示几何先放一放）

1. **基线版**跑同一组 21 个路标 ⇒ BIOS 映像是否完好（`0x080FE000=0x7478654E` 等）？完好 ⇒ 覆盖是**偶发**的。
2. **同一次 boot 里隔 10 秒连读同几个点** ⇒ 值是否在变（有活跃写入者）。
3. **dump `0x080F0000..0x080F03FF`**（BIOS 工作/自检缓冲）⇒ 若出现**同一族图案** ⇒ 写入者就是 BIOS 自己的测试。
4. 我在 BIOS 源码里找那个写"计数器/反码"图案的例程，看它的**范围上限**是否覆盖 `F000:E000`：
   `Next186_SoC-master/186Code/BIOS/BIOS_Next186.asm`、`186Code/BIOS/bootload_BIOS_SD/bootstrap.asm`
5. 修法方向（属"内存映射/AXI 侧"，不碰作者逻辑）：
   **让 F 段不落在可写 DDR 上**（例如该页只读/由 ROM 回填），或**让内存测试的范围排除 F 段**。
   —— 这比继续调显示几何更根本。

**显示几何（105th′）暂缓**：它治的是"每 8 字符重复"，而这一次的乱码/黑屏来自第 1 节的覆盖事故。
